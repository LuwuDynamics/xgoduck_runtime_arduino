# 运动 MCP 与 ToF 前向避障

## 模型与语音入口

| MCP | 使用的现有 ONNX | 行为 |
| --- | --- | --- |
| `Duck.Stand` | `xgoduck_getup` / `xgoduck_walk` | 起身并零速平衡；已坐下时先通过坐站模型起立 |
| `Duck.Forward`、`Duck.Move`、`Duck.Turn` | `xgoduck_walk` | 普通脚前后/侧移、转向 |
| `Duck.SetWalkingMode(mode="roller")` 后 Move/Turn | `xgoduck_roller` | 滚轮脚前后与转向；必须由用户确认装有滚轮 |
| `Duck.Pick` | `xgoduck_pick` | 一次约 4 秒抓取 |
| `Duck.Roulade` | `xgoduck_roulade` | 一次约 1.9 秒翻滚 |
| `Duck.Sit`，随后 `Duck.Stand` | `xgoduck_sitstand` | 坐下后继续保持坐姿和扭矩，Stand 执行原坐到站过渡 |
| `Duck.LeftKick` | `xgoduck_ballkick_left` | 左脚踢球约 0.4 秒后回到平衡 |
| `Duck.RightKick` | `xgoduck_ballkick_right` | 右脚踢球约 0.4 秒后回到平衡 |

工具接受/排队成功不等于实际姿态或位移已经完成。`Duck.GetStatus` 返回
`active_model`、`roller`、`sitstand`、踢球状态、当前/排队/最近动作及 `obstacle_avoidance`。
`Duck.GetToF` 通过只读本地 IPC 直接取主机的 ToF 实时缓存，返回前方最近有效距离（mm/cm）、
有效区域数、帧号、帧龄及完整 8×8 阵列。采样频率仍为 5 Hz；前方限制缓存与传感器缓存
各自带帧号/帧龄，可能相差约一个 50 ms 刷新周期，不冒充同步采样或新触发测量。
不可用时距离为 null，并报告真实原因；不启动摄像头或运动，也不根据测距推断物体类别。
坐下、踢球、抓取、翻滚需先站稳，沿用现有权限、所需关节反馈和控制权检查。
切换普通脚/滚轮脚会清除旧速度和队列，本身不会使能；坐站过渡或踢腿时不能更换模型。
原网页/底层普通行走前进最高 0.2、后退 0.18 m/s；滚轮前后最高 0.4 m/s、转向 ±0.25 rad/s，不侧移。
语音 MCP 使用独立的较低上限：所有方向默认 0.1 m/s、最高 0.15 m/s，包括滚轮模式。

普通“往前走”调用 `Duck.Forward`，省略 `pace` 或 `pace=normal` 时为 0.1 m/s；
用户明确“快点走”“大点步”“最快前进”时，使用 `pace=fast` 的 0.15 m/s。
不接收任意速度参数；时长默认 3 秒，可明确指定 0.1～10 秒。不会因此更换模型。
用户明确慢走、指定速度、后退或侧移时使用 `Duck.Move`；0～0.15 m/s 内的显式数值原样保留，
超过 0.15 的请求会被实际拒绝，不能靠 AI 绕过上限。Move 省略速度时各方向均默认 0.1 m/s。
手机 `RemoteMove` 的百分比映射和转向角速度保持。
这些是模型的速度目标，实际动作仍受原权限、站立确认、队列和 ToF 限制；接受指令不代表已经走满时间或距离。

## 前向限制

VL53L5CX 仍在 MCU `Wire1` 独立进行 8×8、5 Hz 采集。主机后台持续续租只读缓存，
不依赖网页打开；控制线程不发测距 RPC。仅普通行走/滚轮模型的正向速度受限制，
不更改 ONNX 权重、关节映射、起身/抓取/翻滚/坐站/踢球模型的专用输入或原网页资源。

默认取 8×8 图像中央 4×4 区域的最近有效距离，至少需要 3 个有效区域：

- 前进速度不超过 0.2 m/s：距障碍 15 cm 内逐步减速，10 cm 及以内停止前进输入；31 cm 不限速。
- 速度更高时沿用距离裕量：每多 0.1 m/s，停止和减速阈值增加 7.5 cm；0.4 m/s 时为 25/30 cm。
- 受阻后，须连续 3 个不同的有效帧均达到停止距离再加 5 cm，才确认前方清空；普通行走为 15 cm，不再要求退到 40 cm。
- STM32 报告未接 ToF（`absent`）或 ToF 已离线（`offline`）时，遥控和语音可前进，测距避障暂不可用。重新接入传感器后，重启小鸭以重新探测。
- ToF 状态未知、初始化错误、测距超过 600 ms 或前方有效区域不足时暂停前进。确认离线时忽略旧读数。
- 停止保留平衡模式和舵机扭矩，不自动转弯或卸力。后退、侧移和原地转向仍受原运动条件检查。
- 语音前进任务受阻后标记 `blocked`，取消其排队动作，日志记录实际原因。
  数据恢复或确认离线后，需重新说前进。网页/手柄/手机遥控需先松开方向键或回中，
  再前进，也可以先后退或转向。

**受阻是正常执行结果。** 开始前被拦截返回 `status=success`、
`execution.status=blocked`、`started=false`、实际距离/原因和重新发令要求，MCP `isError=false`。
排队执行前受阻同样记录为 `blocked`；执行中受阻保留实际停止记录。
参数越界、权限关闭、舵机/IMU 反馈或控制通信故障继续按真实错误报告，避免用避障结果掩盖故障。

这是前向测距限速，不是路径规划，也不能保证制动距离、发现透明物体、检测悬崖或覆盖两侧/后方。
传感器必须朝前，光学窗口无遮挡；须结合安装高度/俯角实测是否把地面、鸭子自身或外壳当成障碍。
身体趴倒时的近距离读数不能代表站立后的可通行空间。

## 本地配置与诊断

可在板端 `data/obstacle-avoidance.json` 保存以下设置，然后重启 App；分发 ZIP 不包含该设备文件。
缺少配置使用默认开启值；配置损坏时暂停前进并报告原因，聊天仍可启动。

```json
{
  "enabled": true,
  "stop_mm": 100,
  "slow_mm": 150,
  "clear_margin_mm": 50,
  "max_age_ms": 600,
  "rows": [2, 6],
  "columns": [2, 6],
  "min_valid_zones": 3
}
```

`rows`/`columns` 是含起点、不含终点的区域索引。`enabled=false` 可手动关闭前向测距限制。
`GET /api/status` 中的 `obstacle_avoidance` 包括距离、帧龄、有效区域数、减速比例、停止原因、
停止次数和等待重新操作的输入源。未接或离线时分别显示 `state=absent` 或 `state=offline`，
两者均为 `available=false`、`forward_ready=true`，距离为空。`GET /api/tof/status` 提供完整测距阵列。

## MCP 包大小

2026-11-02 只读核验国内运行中的 MQTT 网关：`max_mqtt_payload_size=16000`、
`mcp_client.max_tools_count=60`。16,000 是整个 MQTT 包（含主题、头部等）的字节数，
不是只计算 MCP JSON；不是通用 MCP 标准上限。旧教程的 8,192 不是当前国内部署值。
回归检查使用实际 `send_mcp_message` 序列化后的信封（包含中文 JSON 转义），再预留 512 字节主题/头部空间。
其他部署应核对自己运行中的网关配置。

## 验收

本地回归覆盖模型入口/时长、坐到站排队、脚踢结束/停止、滚轮边界、前向减速/阻挡、
掉线/过期/无效区域、迟到续租、三帧清空、保扭矩及无自动续走；使用模拟 MCU，不驱动实体舵机。
上板后先保持卸力，只读检查传感器、语音、增益和校准，再由用户支撑并留出空间验收身体动作。
先用手在传感器前靠近/移开核对区域和阈值，再进行低速前进测试。
