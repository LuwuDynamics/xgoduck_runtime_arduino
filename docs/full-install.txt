XGO Duck AI 0.3.9 全量安装包 / Full installation package

中文

适用于官方 Debian 13 ARM64 的 Arduino UNO Q。先完成 Linux 账户和 Wi-Fi 设置，让电脑通过局域网 SSH 登录 arduino 用户（UID 1000）。本包安装应用及依赖，不会重刷系统。参考首装环境预留至少 2.5 GiB 可用空间，并分别检查解压位置、/var/lib 和 /home/arduino 所在分区。

1. 在电脑下载 ZIP 和同版本校验文件，核对 SHA-256，SCP 到板上后再次校验。解压到新目录，以 arduino 用户进入该目录，运行 sha256sum -c SHA256SUMS。
2. 若已接舵机，扶稳小鸭并确认卸力。停止正在运行的 App。需要保留旧配置时，先保存同一只鸭子的 data/ 中的持久文件，保留权限和归属；不迁移旧 .cache、data/native/ 和运行时 socket。
3. 检查固定目标 /var/lib/arduino-app-cli/releases/xgoduck-ai-0-3-9-unoq。解压到新目录不会改变它。若目标已存在，只有其中 .xgoduck-full-install.sha256 与本包 xgoduck-ai-0-3-9-unoq.ard 的 SHA-256 完全一致，才能复用。单独安装过 .ard 或同版本重新打包后可能存在冲突。保留已核实可用的安装；明确要求重装时，先保存需保留的数据、停止 App 和相关服务，再处理旧目录。不要伪造收据或覆盖旧目录。
4. 以 arduino 用户运行 bash install.sh，按提示输入 sudo 密码。安装器使用包内依赖、ARM64 镜像和刷写工具，安装预编译 App，配置与固件配套的可靠协议 Router、开机自启并启动 App。握手后目标速率为 2 Mbaud。
5. 如需迁回旧配置，安装结束后先执行 arduino-app-cli app stop /var/lib/arduino-app-cli/releases/xgoduck-ai-0-3-9-unoq，再执行 sudo systemctl stop xgoduck-ai-hardware.service。迁回舵机中位、IMU 标定、设备身份、绑定、区域及手柄等持久设置，核对内容、权限和归属，保留新生成的 native 文件。依次执行 sudo systemctl start xgoduck-ai-hardware.service 和 arduino-app-cli app start --no-prepare /var/lib/arduino-app-cli/releases/xgoduck-ai-0-3-9-unoq。
6. 打开 http://<板子IP>/ 和 http://<板子IP>:9527/，核对 /api/version 为 0.3.9。首次启动完成后，保持舵机卸力，执行 sudo systemctl reboot。重新连接 Wi-Fi SSH，等待网页/API 就绪，确认 boot ID 已改变、默认 App 自动运行且版本正确。已有标定和设置应保留；按实际接线检查舵机、IMU 和可选 ToF。未接线、未标定的项目记录为待完成。
7. 检查 /api/voice/status 和日志。首次未绑定、缺少 USB 麦克风/扬声器或没有公网时，语音未在线不代表安装失败，记录待联网、待绑定或待接设备；进程崩溃和依赖错误仍需处理。只有已绑定、音频设备齐全且公网可用时，才要求语音云连接及音频就绪。账号绑定和云端聊天需要互联网；从驾驶舱进入 AI 语音交互绑定。
8. 按 README 完成剩余步骤：设置舵机编号、组装、统一标定 15 个舵机、单独标定 30 号颈部舵机、标定 IMU、检查默认姿势，再绑定账号并选择智能体。已完成的步骤跳过。断网冷启动可在配置完成后另测，不是未绑定首装的语音在线门槛。

本包包含固定版本的 Arduino 工具、参考系统缺少的 Debian 软件包、ARM64 Docker 基础镜像、Python 环境、STM32 预编译固件及上传工具。包内 APT 源只在安装时使用。包传到板上后可在局域网内完成参考环境的安装。其他 Debian 镜像若缺少包内没有的组件，需要先定位并补齐；不要把本包当作系统镜像。

English

For Arduino UNO Q running the official Debian 13 ARM64 image. Complete Linux account and Wi-Fi setup first, then connect from your computer over LAN SSH as arduino (UID 1000). This package installs the App and dependencies without reflashing the OS. Allow at least 2.5 GiB on the reference first-install system, checking the filesystems holding the extraction directory, /var/lib and /home/arduino separately.

1. Download the ZIP and matching checksum on your computer and verify SHA-256. Transfer with SCP, verify again on the board, and extract into a new directory. As arduino, enter that directory and run sha256sum -c SHA256SUMS.
2. Support Duck and confirm torque is off if servos are connected. Stop running Apps. To retain existing settings, first save this Duck's persistent data/ files with their permissions and ownership. Exclude old .cache, data/native/ and runtime sockets.
3. Check the fixed destination /var/lib/arduino-app-cli/releases/xgoduck-ai-0-3-9-unoq. A different extraction directory does not change it. An existing destination can be reused only if its .xgoduck-full-install.sha256 exactly matches the SHA-256 of this bundle's xgoduck-ai-0-3-9-unoq.ard. A separately installed .ard or a repack with the same version may conflict. Retain a verified working installation; for an explicitly requested reinstall, save the data to retain, stop the App and related services, then handle the old directory. Do not fabricate a receipt or overwrite the directory.
4. Run bash install.sh as arduino and supply the sudo password when prompted. The installer uses bundled dependencies, ARM64 images and upload tools, installs the precompiled App, configures the matching reliable Router and autostart, then starts the App. The target link speed after negotiation is 2 Mbaud.
5. To restore saved settings after installation, run arduino-app-cli app stop /var/lib/arduino-app-cli/releases/xgoduck-ai-0-3-9-unoq, then sudo systemctl stop xgoduck-ai-hardware.service. Restore persistent servo centers, IMU calibration, device identity, binding, region and gamepad settings. Verify contents, permissions and ownership, retaining the new native files. Run sudo systemctl start xgoduck-ai-hardware.service, then arduino-app-cli app start --no-prepare /var/lib/arduino-app-cli/releases/xgoduck-ai-0-3-9-unoq.
6. Open http://<board-ip>/ and http://<board-ip>:9527/ and check that /api/version returns 0.3.9. Once the first startup finishes, keep torque off and run sudo systemctl reboot. Reconnect over Wi-Fi SSH, wait for the web pages/API, and confirm a changed boot ID, automatic startup of the default App and the correct version. Existing calibration and settings must remain intact. Check connected servos, IMU and optional ToF; record unwired or uncalibrated hardware as unfinished setup.
7. Check /api/voice/status and logs. On a first install without account binding, USB audio or internet, offline voice does not mean installation failed. Record pending network, binding or hardware setup, while investigating process crashes and dependency errors. Require voice cloud connectivity and audio readiness only when binding, audio hardware and internet access are all available. Account binding and cloud chat need internet; open Link AI in the cockpit.
8. Complete the remaining README steps: number the servos, assemble Duck, calibrate all 15 servo centers together, set ID 30 separately, calibrate the IMU, check Default pose, then bind an account and select an agent. Skip completed steps. Offline cold boot can be tested after setup; online voice is not a prerequisite for an unbound first installation.

The bundle includes pinned Arduino tools, Debian packages missing from the reference system, the ARM64 Docker base image, Python environment, precompiled STM32 firmware and upload tools. Its local APT source is used only during installation. Once transferred, it can install over the LAN on the reference environment. Other Debian images may need components outside the bundle; identify and supply those first. This package is not an OS image.
