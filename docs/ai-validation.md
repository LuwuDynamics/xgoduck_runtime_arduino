## 补查中复现并修复的问题

1. **慢速硬件调音量会卡住实时音频。** 原实现让 `amixer` 与 PortAudio PCM 回调共用一把锁。用受控阻塞的 mixer 命令复现后，分开硬件操作锁和短时间状态读取锁；混音命令未返回时，PCM 回调仍能完成。
2. **聊天关闭后的旧 MQTT 回调可能影响新连接。** 复现了关闭后仍创建连接、创建过程中关闭却继续连接、旧断线回调清掉新连接状态，以及重连定时任务未取消。现在检查协议关闭状态和客户端身份，协调创建与关闭，先断开再后台等待旧网络线程，关闭时取消重连任务。
3. **无屏配网不能依赖 USB 音频或已启动的聊天 SDK。** 独立的主机 BluFi 服务开机广播；绑定检查不打开声卡；没有麦克风/扬声器时使用 NoAudio 保持 MQTT/MCP。声卡移除和重新插入会重新建立音频会话。
4. **Wi-Fi 长操作、分片通知和 GATT 重连可能使手机超时。** 补齐原生 iOS 所需的 CRC 和 ACK，20 字节通知分片保持连续；空扫描有完成帧；重连重置序号；配网在手机 30 秒超时前报告失败，并取消清理操作。失败时保留并恢复原 Wi-Fi 配置。
5. **语言/手机选区可能错用服务器或缓存。** 改为板端手动选择 `cn/global`，未选区不访问聊天云端。手机写入的 `cloud:*` 自定义帧被忽略。换区按 OTA 地址和设备身份校验缓存，MCP 凭据刷新也走同一检查，不调用旧 SDK 按语言回退的缓存路径。
6. **开启手机遥控权限会触发无必要的聊天/MCP 重连。** 运动权限通过共享持久配置直接生效，不再作为重建聊天会话的条件。默认仍不授权、不启动舵机。
7. **旧 USB 开机服务可能与新 App 切换 Host 竞争。** 安装器停用已有的旧 Duck USB/手柄服务，保留 unit 文件及旧 App；提供显式切回步骤。第二只 UNO Q 上迁移已经执行，原 App 文件保持不变。

之前的基础检查还修正了 MCP 把“请求已接受”误报为错误，以及聊天暂停后旧任务/旧运动租约仍可能生效的问题。
